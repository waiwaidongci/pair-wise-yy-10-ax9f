# zfl-42 漆线雕工坊 · 返工令与补线工位台

独立静态前端应用，直接打开 `index.html` 即可使用（数据存 localStorage）。

## 脚本结构（业务模型 / 排期判定 / 看板交互三层分离）

| 文件 | 职责 |
| --- | --- |
| `js/models.js` | 业务模型：作品、返工令、补线材料、操作者、复核放行结论的数据结构与不变量；localStorage 落库、旧版数据迁移、种子数据。不碰 DOM。 |
| `js/scheduling.js` | 排期判定：备料齐套检查、同工序每日容量（3 件）、交付日期近者先排序、顶入/挤下、被挤下件保留原因、按日整盘重算。纯判定，不碰 DOM。 |
| `js/kanban.js` | 看板交互：作品工序看板与补线工位台的渲染、对话框、事件委托、筛选导出。规则只调用前两层，不自行实现。 |

## 返工令业务规则

- **一件缺陷作品只能有一张未完结返工令**；开令必须记录责任工序、补线材料（名称/需求量/已备量/单位）、操作者、承诺完成日。
- **材料未备齐，整令不得进入排期**：缺料令停在「待备料」，补齐自动转「待排期」，备料被调低则退回。
- **同一责任工序每日最多 3 件**：超容后按作品交付日期近者先（承诺完成日、开令时间为次序）；单件申请时若比工位上最晚者更近则顶入。
- **被挤下的件保留原排期原因**，状态回「待排期」（queue.state=bumped），可继续申请其它日期或参与整盘重算。
- **完成返工须另一人复核**：操作者本人不能复核；不通过退回返工中，通过才放行；未持有效放行结论的缺陷作品不能切到「待交付」。
- **更正任一派工字段（责任工序/补线材料/操作者/承诺完成日）**：旧排期与放行结论立即标记失效，旧令原样留档（可沿 supersede 链追溯履历），开出 revision+1 的续次令重新备料排期；失效旧令不再占用工位。刷新页面后队列与作品履历仍一致。

## 看板

- 工序看板：贴线中 / 待阴干 / 上金粉 / 待返工 / 待交付，支持状态流转、记缺陷、开返工令、筛选与交付排序。
- 补线工位台：待备料 → 待排期 → 工位排期（按工序分块，显示 占用/3 与被挤下件）→ 待复核 → 已完结；底部为留档旧令。
- 支持 JSON 导出。
