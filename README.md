# zfl-42 小型漆线雕工坊管理 · 返工令与补线工位台

独立静态前端应用，直接打开 `index.html` 即可使用（数据存于浏览器 localStorage）。

## 代码结构

脚本按职责拆为三个非测试文件，由 `index.html` 顺序加载：

| 文件 | 职责 |
| --- | --- |
| `js/models.js` | 业务模型：作品、返工令、补线材料实体与不变量、localStorage 持久化 |
| `js/scheduler.js` | 排期判定：材料闸门、同工序每日 3 件上限、交付日近者优先与顺延、看板队列重算（纯函数） |
| `js/kanban.js` | 看板交互：作品四列看板、补线工位台、开具/更正返工令、开工/完成/他人复核等全部 DOM 操作 |

排期结果不落库，每次渲染/刷新都由 `WorkshopScheduler.recompute()` 从作品与返工令履历重算，保证刷新后队列与作品履历一致。

## 业务规则

- **一作品一未完结令**：只有登记缺陷的作品可开返工令；已有未完结令时拒绝重复开具。
- **派工四要素**：责任工序、补线材料（可多项、逐项标记备齐）、操作者、承诺完成日。
- **材料闸门**：任一材料未备齐，整令停留在「待备料」，不进入排期，也不能开工。
- **每日容量**：同一责任工序每日最多 3 件；超出时交付日期近者先排入当天，被挤下的件顺延到下一可用日期，卡片保留原排期原因（承诺完成日）并标注顺延。
- **他人复核**：返工完成后进入「待复核」，复核人不得与操作者相同；未复核对的作品不能切到「待交付」；复核可驳回返工。
- **更正留档**：更正任一派工字段（工序/材料/操作者/承诺日）会把旧令原样归档为「旧令留档」、旧排期与放行结论立即失效，另立新令（`revisionOf` 链接旧令）并重新排期；作品履历同步记录。

## 看板

- 作品看板：贴线中 / 待阴干 / 上金粉 / 待交付，转「待交付」前自动做返工放行校验。
- 补线工位台：待备料 / 已排期 / 返工中 / 待复核 / 已放行 / 旧令留档，顶部为未来 5 天各工序容量条。
- 今日待阴干、缺陷作品、最近交付列表；筛选、排序、JSON 导出、恢复演示数据。
